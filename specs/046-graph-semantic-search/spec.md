# Feature Specification: 그래프 탭 의미 기반 코드 검색

**Feature Branch**: `046-graph-semantic-search`

**Created**: 2026-07-11

**Status**: Draft

**Input**: User description: 그래프 탭 Overview 패널에 자연어(업무 말) 기반 관련 코드 검색을 추가한다. 이름검색 아래 "의미 기반 관련 코드" 섹션, 버튼 하나로 시작, 40초 스트림 진행 표시, 뭉치 결과를 캔버스로, ⌘K 라우팅 교정, 결과 클릭 시 검색 유지.

## 배경 / 문제

그래프 탭에는 검색이 두 곳 있고 **둘 다 이름(문자열)만** 검색한다.

- **왼쪽 Navigator 트리 검색** = 이미 화면에 있는 트리를 좁힌다(filter).
- **오른쪽 Overview 노드검색** = 노드를 찾아 캔버스에 올린다(retrieve). 하지만 이름 일치만 된다.

사용자가 함수 이름을 모른 채 **업무 말**("주문을 취소하면 결제와 재고가 어떻게 원복되는가", "배송비 계산")로 관련 코드를 찾으려 하면 방법이 없다. 이름이 안 겹치면 아무것도 안 나온다. 이 기능은 오른쪽 Overview 노드검색 **아래에** "의미 기반 관련 코드" 섹션을 붙여, 뜻으로 관련 코드 뭉치를 찾아 캔버스로 가져오게 한다.

검색 자체(임베딩·후보검색·재순위·뭉치)는 백엔드가 별도 구현한다. **이 명세의 범위는 프론트 표시 계층**: 검색 요청/취소, 스트림 진행 표시, 뭉치 결과 렌더, 기존 검색 UI 재배치, 진입점(⌘K) 배선이다. 새 백엔드 로직·새 raw API 클라이언트는 만들지 않는다(기존 게이트웨이 경유 스트림 클라이언트 재사용).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 업무 말로 관련 코드 뭉치를 찾아 캔버스에 올린다 (Priority: P1)

사용자가 그래프 탭 Overview 패널의 검색칸에 업무 말("주문을 취소하면 결제와 재고가 어떻게 원복되는가")을 입력한다. 이름 일치 결과가 즉시 뜨고, 그 아래 "의미로 더 찾기 · 약 40초" 버튼이 보인다. 버튼을 누르면 그 자리가 진행 표시로 바뀌어 지금 무슨 단계를 하는지·몇 초 지났는지를 보여준다. 약 40초 뒤 진행 표시가 관련 코드 **뭉치 목록**(각 뭉치 = 여러 코드노드, 유사도 % 표시)으로 바뀐다. 뭉치를 클릭하면 그 노드들이 관계와 함께 캔버스에 올라온다.

**Why this priority**: 이 기능의 존재 이유 그 자체. 이름을 모르는 사용자가 코드를 찾는 유일한 경로이며, 나머지 스토리(진행 표시·안내·진입점)는 이 흐름을 견디게 하는 보조다.

**Independent Test**: Overview 검색칸에 업무 말 입력 → "의미로 더 찾기" 버튼 클릭 → 진행 표시가 뜨고 → 결과 뭉치가 나오고 → 뭉치 클릭 시 해당 노드들이 캔버스에 추가되는지 확인. 이 하나만으로 "이름 모르고 코드 찾기"라는 가치가 성립한다.

**Acceptance Scenarios**:

1. **Given** Overview 패널이 열려 있고 검색칸에 업무 말이 입력된 상태, **When** "의미로 더 찾기" 버튼을 누른다, **Then** 이름 결과 아래 그 자리에 진행 표시(현재 단계 + 경과 초)가 나타난다.
2. **Given** 검색이 진행 중인 상태, **When** 백엔드가 결과를 반환한다, **Then** 진행 표시가 뭉치 목록으로 바뀌고 각 뭉치에 제목·유사도 %·소속 노드가 보인다.
3. **Given** 결과 뭉치 목록이 떠 있는 상태, **When** 한 뭉치를 클릭한다, **Then** 그 뭉치의 노드들이 관계와 함께 캔버스에 추가되고, **검색칸과 결과 목록은 그대로 유지된다**(사라지지 않는다).
4. **Given** 버튼을 누르지 않은 상태, **When** 검색칸에 글자만 입력·수정한다, **Then** 의미검색 서버 요청은 발생하지 않는다(이름검색만 동작).

---

### User Story 2 - 40초를 견디게 하는 진행 표시와 취소 (Priority: P1)

의미검색은 최대 약 40초 걸린다. 사용자는 그동안 지금 무슨 일이 되고 있는지, 얼마나 지났는지 알아야 하고, 언제든 멈출 수 있어야 한다. 진행 상황은 결과가 나올 그 자리(인라인)에 단계·경과 초·취소로 표시되고, 사용자가 다른 노드를 클릭하거나 탭을 옮겨도 상단 툴바의 얇은 배지("의미검색 중 · N초")로 계속 돌고 있음을 안다.

**Why this priority**: 40초짜리 무응답 대기는 "고장 났다"로 읽힌다. 진행 표시·취소가 없으면 P1 스토리(검색)가 실사용에서 무너진다. 그래서 함께 P1.

**Independent Test**: 검색을 시작한 뒤 ① 인라인에 단계가 순차로 바뀌고 경과 초가 증가하는지 ② 상단 배지가 뜨는지 ③ 취소를 누르면 진행이 멈추고 이후 결과·에러가 오지 않는지 확인.

**Acceptance Scenarios**:

1. **Given** 검색이 진행 중, **When** 백엔드가 단계 진행을 순차로 보낸다, **Then** 인라인 표시가 그 단계 문구를 순서대로 보여주고 경과 초가 계속 증가한다.
2. **Given** 검색이 진행 중, **When** 사용자가 다른 노드를 클릭하거나 탭을 옮긴다, **Then** 상단 툴바에 "의미검색 중 · N초" 배지가 계속 보인다.
3. **Given** 검색이 진행 중, **When** 사용자가 취소를 누른다, **Then** 진행 표시가 사라지고 이후 결과·에러 이벤트가 화면에 반영되지 않으며, 이름 결과와 검색칸은 그대로 남는다.
4. **Given** 검색이 진행 중, **When** 사용자가 같은 칸에서 새 검색을 시작한다, **Then** 이전 검색은 취소되고 새 검색의 진행이 표시된다(진행 표시가 겹치지 않는다).

---

### User Story 3 - 검색 진입점과 두 검색칸의 역할 정리 (Priority: P2)

지금은 ⌘K 전역 검색이 그래프 탭에서 왼쪽 트리 필터로 간다("찾아줘"인데 "목록 좁히기"로 감 = 거꾸로). 또 두 검색칸이 둘 다 "…검색"이라 어디에 쳐야 할지 불명확하다. ⌘K를 Overview 검색으로 보내고, 두 칸의 안내 문구가 역할을 말하게 한다(왼쪽 "목록에서 좁히기", 오른쪽은 이름·업무 말 둘 다 받음).

**Why this priority**: 이게 없으면 새 의미검색에 단축키로 도달할 방법이 없고 사용자는 어디에 칠지 매번 고민한다. 다만 P1 없이는 무의미하므로 P2.

**Independent Test**: 그래프 탭에서 ⌘K(또는 Ctrl+K) → 상단 검색 입력에 포커스 후 Enter → Overview 검색으로 라우팅되는지 확인. 두 검색칸 placeholder가 역할을 구분해 보여주는지 확인.

**Acceptance Scenarios**:

1. **Given** 그래프 탭이 활성, **When** ⌘K/Ctrl+K로 상단 검색에 입력 후 실행한다, **Then** 그 질의가 Overview 검색으로 전달된다(왼쪽 트리 필터가 아니라).
2. **Given** 그래프 탭, **When** 두 검색칸을 본다, **Then** 왼쪽은 "목록에서 좁히기", 오른쪽은 이름·업무 말을 함께 받는다는 안내가 보인다.

---

### User Story 4 - 실패·빈 상태에서 침묵하지 않는다 (Priority: P2)

결과가 0건이거나, 이 그래프에 검색 임베딩이 없거나, 검색이 실패하면 화면이 그 자리에서 이유와 다음 행동을 말한다. 검색칸이 빈 처음 상태에도 짧은 한 줄 안내가 있다. 예시 질의 칩·도움말 아이콘은 만들지 않는다.

**Why this priority**: 40초 기다린 뒤의 침묵은 "고장"으로 읽힌다. 실패한 순간이 사용자가 안내를 읽는 유일한 순간이다. P1 흐름의 안전망이라 P2.

**Independent Test**: ① 임베딩 없는 그래프에서 검색 → 사유 안내 표시 ② 결과 0건 → "못 찾음 + 다시 쓰는 법" 안내 ③ 빈 검색칸 → 한 줄 안내 노출 확인.

**Acceptance Scenarios**:

1. **Given** 검색 결과가 0건으로 정상 종료, **When** 결과가 반영된다, **Then** 그 자리에 "관련 코드를 못 찾았습니다"와 다시 쓰는 법(업무 용어로·자세히) 안내가 나타난다.
2. **Given** 이 그래프에 검색 임베딩이 없음, **When** 검색을 시도한다, **Then** 서버가 보낸 사유("이 그래프에는 검색 임베딩이 없습니다")가 그 자리에 표시된다.
3. **Given** 검색칸이 비어 있음, **When** Overview를 본다, **Then** 짧은 한 줄 안내가 보이고, 예시 질의 칩·도움말 아이콘은 없다.

---

### Edge Cases

- **짧은 질의**: "배송비 계산"처럼 두 단어짜리도 유효한 질의다. 글자 수·단어 수로 자연어/키워드를 판정하거나 검색을 막지 않는다(형태 규칙 금지).
- **검색 중 결과 클릭**: 진행 중에는 아직 뭉치가 없으므로 클릭 대상이 없다(이름 결과는 평소처럼 클릭 가능).
- **취소 후 지연 도착 이벤트**: 취소된 검색의 스트림 이벤트가 늦게 도착해도 화면에 반영하지 않는다.
- **연속 검색**: 결과가 뜬 뒤 다시 "의미로 더 찾기"를 누르면 새 검색이 이전 결과를 대체한다.
- **패널 닫힘**: 검색 진행 중 Overview 패널을 닫아도 상단 배지로 진행을 알 수 있고, 다시 열면 진행/결과가 이어져 보인다.
- **캔버스 매칭 실패**: 결과 뭉치의 노드 식별자가 현재 그래프에 없으면 그 노드는 조용히 누락하지 않고, 최소한 캔버스에 올릴 수 없음을 알 수 있어야 한다(무반응 금지).

## Requirements *(mandatory)*

### Functional Requirements

#### 검색 실행 (US1)

- **FR-001**: 시스템은 Overview 노드검색 **아래에** "의미 기반 관련 코드" 섹션을 두어야 한다. 왼쪽 Navigator 트리 검색과 오른쪽 이름 검색·이름 결과의 기존 동작·위치는 바뀌지 않는다.
- **FR-002**: 의미검색은 **명시적 실행(버튼)** 으로만 시작한다. 버튼을 누르기 전에는 의미검색 서버 요청이 발생하지 않는다(검색칸 입력·수정만으로 자동 실행 금지). 상태 토글이 아니라 행동 버튼이다.
- **FR-003**: 사용자는 이름·자연어 구분 없이 같은 검색칸에 질의를 입력한다. 시스템은 질의의 **길이·형태로 분기하지 않는다**(자연어 판정·해피패스 금지). 무엇을 입력하든 이름검색은 즉시, 의미검색은 버튼으로 실행된다.
- **FR-004**: 결과 뭉치를 선택하면 그 뭉치의 노드들이 **관계와 함께 캔버스에 추가**된다. 기존 캔버스 내용은 유지·증가만 하며 감소하지 않는다.
- **FR-005**: 결과 뭉치를 선택해도 **검색 상태(검색칸·이름 결과·의미 결과 목록)가 유지**되어야 한다. 결과 탐색 중 검색 UI가 다른 화면(노드 상세)으로 통째 전환되어 검색 맥락이 소실되지 않아야 한다.

#### 진행 표시·취소 (US2)

- **FR-006**: 검색이 진행되는 동안 결과가 나올 그 자리(인라인)에 **현재 단계 문구·경과 시간·취소 수단**을 표시해야 한다.
- **FR-007**: 단계 문구는 백엔드가 스트림으로 보내는 label을 **그대로** 표시한다. 프론트는 단계 이름을 자체 판정·창작하지 않는다.
- **FR-008**: 검색이 진행되는 동안 상단 툴바에 **진행 배지**("의미검색 중 · N초" 형태)를 노출해, 사용자가 패널을 벗어나 다른 노드·탭을 봐도 진행을 인지할 수 있어야 한다. 하단 분석 진행 패널·콘솔은 이 용도로 쓰지 않는다.
- **FR-009**: 사용자는 진행 중 검색을 **취소**할 수 있어야 한다. 취소하면 진행 표시가 사라지고, 취소된 검색의 이후 이벤트(결과·에러 포함)는 화면에 반영되지 않으며, 이름 결과·검색칸은 유지된다.
- **FR-010**: 새 검색을 시작하면 **이전 진행 중 검색은 취소**되어야 한다. 두 검색의 진행·결과가 섞이지 않아야 한다.

#### 진입점·역할 (US3)

- **FR-011**: 그래프 탭에서 상단 전역 검색(⌘K/Ctrl+K)의 실행은 **Overview 검색으로** 라우팅되어야 한다(왼쪽 트리 필터가 아니라).
- **FR-012**: 두 검색칸의 안내 문구가 역할을 구분해야 한다 — 왼쪽 Navigator = 목록 좁히기, 오른쪽 Overview = 이름·업무 말을 함께 받음. Navigator 트리 검색의 동작 자체는 바뀌지 않는다(문구만).

#### 안내·실패·빈 상태 (US4)

- **FR-013**: 결과가 0건이면 "못 찾음"과 **다시 쓰는 법 안내**(업무 용어로·자세히)를 그 자리에 표시한다. 0건은 오류가 아니다.
- **FR-014**: 검색이 오류로 끝나면 서버가 보낸 **사유 메시지를 그 자리에** 표시한다(예: 이 그래프에 검색 임베딩 없음).
- **FR-015**: 검색칸이 빈 처음 상태에는 **짧은 한 줄 안내**만 둔다. **예시 질의 칩과 도움말 아이콘은 만들지 않는다.** 안내는 검색칸 placeholder·실행 버튼 아래·실패 안내의 세 자리에 짧게 둔다. 실행 버튼 아래 안내는 조건 없이 항상 같은 한 줄이다.

#### 통신·계약 (전 스토리 공통)

- **FR-016**: 의미검색 요청은 **기존 게이트웨이 경유·세션 헤더 규약**을 따른다(하드코딩 포트·raw fetch 금지). 대상 그래프 DB는 세션 헤더로 지정되며, 검색은 사용자가 현재 보고 있는 그래프와 같은 DB를 대상으로 한다.
- **FR-017**: 프론트는 결과 노드의 **논리 식별자(node.id 속성)** 로 캔버스 노드를 매칭한다. 별도 내부 식별자 매핑을 추가하지 않는다.
- **FR-018**: 검색 임베딩은 분석 파이프라인의 후처리 단계(embed)에서 생성·저장된다. 이 단계의 진행은 **기존 분석 진행 표시로 이미 노출**된다(본 기능이 별도 표시를 추가하지 않는다). 임베딩이 없는 그래프에서의 검색 실패 처리는 FR-014를 따른다.

### Key Entities *(include if feature involves data)*

- **의미검색 세션(검색 실행 1건)**: 하나의 질의에 대한 진행 상태. 속성 — 질의 문자열, 진행 단계 목록(순서대로 수신), 현재 단계, 경과 시간, 진행/완료/취소/오류 상태, 취소 수단. 한 Overview 패널에는 한 번에 하나의 활성 검색 세션이 있다(새 검색이 이전을 대체).
- **결과 뭉치(cluster)**: 의미적으로 묶인 관련 코드 묶음. 속성 — 뭉치 식별자, 사람이 읽는 제목, 유사도(관련도, 0~1), 소속 노드 목록. 뭉치 = 캔버스에 함께 올라가는 단위.
- **뭉치 소속 노드**: 코드노드 참조. 속성 — 논리 식별자(캔버스 매칭 키), 표시 이름, 종류(라벨), 노드별 관련도. 캔버스에 관계와 함께 추가되는 대상.
- **진행 단계 이벤트**: 백엔드가 스트림으로 보내는 단일 진행 알림. 속성 — 단계 식별자, 표시 문구(그대로 표시), 부가 진척 문구(선택).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 이름이 안 겹치는 업무 말 질의(예: "하루 장사 끝나고 돈 맞춰보는 거 어디서 하나")로도 사용자가 관련 코드 뭉치를 찾아 캔버스에 올릴 수 있다(이름검색만으로는 0건이던 질의에서 성공).
- **SC-002**: 의미검색을 시작한 순간부터 결과가 나올 때까지, 사용자는 **어느 시점에 화면을 봐도** 지금 검색이 진행 중이라는 사실과 경과 시간을 확인할 수 있다(무응답 구간 0).
- **SC-003**: "검색 → 결과 뭉치 클릭" 시나리오에서 검색 맥락 소실률 0 — 뭉치를 클릭해도 검색칸·결과 목록이 유지되며, 사용자는 곧바로 다른 뭉치를 클릭할 수 있다.
- **SC-004**: "검색 → 결과 클릭" 후 기존 캔버스 노드 수가 감소하지 않는다(유지 또는 증가만). 캔버스 유실 사고 0.
- **SC-005**: 버튼을 누르지 않는 한 의미검색 서버 요청은 0건이다(그래프 탭을 쓰는 기존 사용자에게 서버 부하·동작 변화 없음).
- **SC-006**: 검색 실패·0건·임베딩 없음의 세 경우 모두에서 화면이 침묵하지 않고 사유·다음 행동을 그 자리에 안내한다(침묵 0건).
- **SC-007**: 진행 중 취소 시, 취소 이후 도착하는 이벤트가 화면에 반영되지 않는다(취소 후 결과 튐 0건).

## Assumptions

- 의미검색·임베딩·뭉치 산출은 백엔드가 별도 구현하며, 본 기능은 확정된 계약(NDJSON 스트림: 진행 이벤트 → 결과 이벤트 → 종결, 오류/0건 처리 포함)을 소비하는 **표시 계층**이다.
- 검색 대상 그래프는 사용자가 현재 그래프 탭에서 보고 있는 그래프와 동일 DB이며, 세션 헤더로 지정된다.
- 결과 노드의 논리 식별자(node.id 속성)는 현재 그래프의 캔버스 노드 식별 체계와 동일하다(코드 확인 완료 — 프론트 매칭 무변경).
- 검색 최대 소요는 약 40초로 가정한다(진행 표시·취소·상단 배지 설계의 근거). 실제 값은 백엔드 성능에 따르며, 표시 계층은 특정 초를 하드코딩하지 않는다.
- 취소는 요청 중단(연결 끊기) 방식이며 별도 취소 엔드포인트는 없다. 동시 여러 검색은 서버가 허용하되, 본 패널은 한 번에 하나의 활성 검색만 유지한다.
- 기존 게이트웨이 경유 스트림 소비 계층을 재사용하며, 새 raw 통신 경로는 추가하지 않는다(헌법 III).
- 이 기능은 새 URL 라우트 없이 기존 그래프 탭 안에서 동작한다(헌법 I). 변경은 code-analysis·shared(TopToolbar) 범위에 한정한다(헌법 II).
