# Feature Specification: 노드 검색 결과 위치 교정 (캔버스 비우기 오조작 방지)

**Feature Branch**: `042-search-dropdown-anchor`

**Created**: 2026-06-28

**Status**: Draft

**Input**: Overview(노드 상세 패널 미선택 상태)의 노드 이름 검색에서, 검색 결과 목록이 입력창이 아니라 검색 영역 전체 바닥에 나타나 그 사이에 항상 떠 있는 "캔버스 비우기" 버튼이 입력→결과 클릭 경로를 가로막아, 결과를 누르려다 캔버스를 통째로 비우는 오조작이 발생하는 문제의 근본수정.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 검색하고 결과를 누르는 동안 캔버스가 지워지지 않는다 (Priority: P1)

분석 그래프 Overview에서 사용자가 노드 이름 검색칸에 글자를 입력하면, 검색 결과가 **입력칸 바로 아래**에 나타난다. 사용자는 시선과 커서를 입력칸 → 바로 아래 결과로 자연스럽게 옮겨 원하는 노드를 클릭하며, 그 경로 어디에도 "캔버스 비우기"처럼 화면을 통째로 비우는 버튼이 끼어 있지 않아 실수로 캔버스를 날릴 일이 없다.

**Why this priority**: 현재는 입력칸과 결과 목록 사이에 파괴적(되돌리기 어려운) "캔버스 비우기" 버튼이 끼어 있어, 검색→선택이라는 가장 흔한 동작 중에 캔버스 전체가 지워지는 사고가 실제로 발생한다. 데이터 손실성 오조작이므로 최우선.

**Independent Test**: Overview 검색칸에 글자를 입력 → 결과 목록이 입력칸 바로 아래에 뜨는지, 그리고 입력칸에서 첫 번째 결과까지의 직선 경로 위에 "캔버스 비우기" 버튼이 노출되지 않는지 확인. 첫 결과를 클릭 → 해당 노드만 캔버스에 올라오고 기존 캔버스가 비워지지 않음.

**Acceptance Scenarios**:

1. **Given** Overview가 열려 있고 캔버스에 노드가 있는 상태, **When** 검색칸에 글자를 입력한다, **Then** 검색 결과 목록이 입력칸 바로 아래에 나타나고 그 사이에 "캔버스 비우기" 버튼이 보이지 않는다.
2. **Given** 검색 결과 목록이 떠 있는 상태, **When** 입력칸에서 첫 결과까지 커서를 내려 결과를 클릭한다, **Then** 해당 노드만 캔버스에 추가되고 기존 캔버스 내용은 그대로 유지된다(비워지지 않는다).
3. **Given** 검색칸이 비어 있어 결과 목록이 닫힌 상태, **When** Overview를 본다, **Then** "캔버스 비우기" 버튼은 지금처럼 노드 패널 안에서 정상적으로 보이고 동작한다.

---

### Edge Cases

- 검색 결과가 0건일 때: "검색 결과가 없습니다" 안내도 입력칸 바로 아래에 나타나며, 마찬가지로 그 위치에 "캔버스 비우기" 버튼이 끼지 않는다.
- 검색 결과가 길어 스크롤이 필요할 때: 목록을 아래로 훑어 내려가는 동안에도 "캔버스 비우기" 버튼이 결과 목록 위로 드러나 잘못 눌리지 않는다.
- 검색칸을 비우거나 검색을 닫으면: 결과 목록이 사라지고 "캔버스 비우기" 버튼이 원래 자리에서 다시 정상 노출된다(레이아웃이 튀지 않는다).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 노드 이름 검색 결과 목록은 검색 입력칸을 기준으로 **그 바로 아래**에 나타나야 한다(검색 영역 전체의 바닥이 아니라 입력칸 직하).
- **FR-002**: 검색 결과 목록이 떠 있는 동안에는, 입력칸에서 결과까지의 클릭 경로 위에 "캔버스 비우기" 버튼이 노출되지 않아야 한다.
- **FR-003**: "캔버스 비우기" 버튼과 노드 검색 입력은 **둘 다 노드 패널(Overview) 안에 그대로** 유지되어야 한다(다른 화면 영역으로 이동하지 않는다).
- **FR-004**: 검색이 닫혀 결과 목록이 없을 때 "캔버스 비우기" 버튼은 종전과 동일하게 노출·동작해야 한다(기능·표시 조건 회귀 없음).
- **FR-005**: 검색 결과를 선택하는 동작은 종전과 동일하게 해당 노드만 캔버스에 추가하며, 캔버스 비우기 동작은 검색·선택 흐름과 분리되어 의도적으로만 실행되어야 한다.
- **FR-006**: 이 수정은 검색·캔버스 비우기의 동작 자체를 바꾸지 않고 **요소의 위치(나타나는 기준점)만** 바로잡는다. 새 분기·플래그·상태를 추가하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 검색어를 입력했을 때 결과 목록의 상단이 입력칸 바로 아래에 위치한다(입력칸과 결과 목록 사이에 다른 클릭 가능한 버튼이 0개).
- **SC-002**: "검색→첫 결과 클릭" 시나리오에서 캔버스가 비워지는 사고 발생률이 0이 된다(기존 캔버스 노드 수가 선택 동작 후에도 유지·증가만 함, 감소 없음).
- **SC-003**: 검색을 닫은 상태에서 "캔버스 비우기" 버튼은 100% 종전과 동일하게 노출·동작한다(기능 회귀 0).

## Assumptions

- 대상은 분석 그래프 Overview의 "노드 상세 패널 미선택" 상태에 있는 노드 이름 검색 UI 한 곳이다(다른 검색/패널은 범위 밖).
- "캔버스 비우기" 버튼의 표시 조건(캔버스에 노드가 있을 때만 노출)과 동작(캔버스 비우기 + 선택·활성 필터 해제)은 변경하지 않는다.
- 검색 결과 산출·정렬·표시 내용 및 결과 선택 시의 캔버스 반영 로직은 변경하지 않는다.
