# Phase 1 Data Model: 응집도·결합도 그래프 보기

**Date**: 2026-07-21 · **Plan**: [plan.md](./plan.md)

새 저장소나 새 백엔드 필드를 만들지 않는다. 이미 로드된 그래프에서 **파생되는 화면 모델**만 정의한다.

## 1. 입력 (기존 그래프 — 변경 없음)

| 항목 | 출처 | 이번 기능이 읽는 이유 |
|---|---|---|
| 노드 `labels` | Neo4j | 층 판정(`nodeClassify`의 `CONTAINER_LABELS`/`CALLABLE_LABELS`/`TABLE`) |
| 노드 `properties.name` | Neo4j | 표시명 |
| 노드 `properties.risk_level` | `health_metrics_step` | 문제 목록 |
| 노드 `properties.in_call_cycle` | `health_metrics_step` | 문제 목록 |
| `BELONGS_TO` | 그릇 → 영역(PACKAGE) | 영역 소속 |
| `HAS_MEMBER` | 모듈 → 루틴 | 모듈 소속 |
| `PARENT_OF` | 상위 → 하위(구문 중첩) | R/W 출발점을 소유 루틴으로 해소 |
| `CALLS` | 루틴 → 루틴 | 영역 간 호출 집계 |
| `READS` / `WRITES` | 구문·루틴 → 테이블 | 테이블 주인 판정, 영역 간 데이터 접근 집계 |

## 2. 층 (Layer)

```
영역(Area)  ─ 포함 ─▶  모듈(Module)  ─ 포함 ─▶  루틴(Routine)  ─ 포함 ─▶  내부(Inner)
  PACKAGE               CONTAINER_LABELS        CALLABLE_LABELS         그 외 전부
```

- **판정처는 `nodeClassify.ts` 하나다.** 059는 판정 로직을 새로 쓰지 않고 이 결과를 읽는다.
- `내부`는 라벨 목록으로 정의하지 않는다 — 위 세 층 어디에도 걸리지 않으면 내부다. 그래서 처음 보는
  antlr 타입이 나와도 규칙을 고칠 일이 없다(전략 분기 0).
- **테이블은 층이 아니다.** 별도 종류이며 §4의 규칙으로 영역에 소속된다.

### 영역 소속 해소

```
루틴 →(HAS_MEMBER 역방향)→ 모듈 →(BELONGS_TO)→ 영역
```

어느 단계든 끊기면 `'기타'` 묶음에 속한다(FR-030). `'기타'`는 다른 영역과 완전히 같은 규칙으로
접히고 펼쳐진다.

### R/W 출발점 해소

`READS`/`WRITES`의 출발 노드는 루틴 자신일 수도, 그 안에 중첩된 구문일 수도 있다(실측 근거는
research R2). `PARENT_OF`를 거슬러 올라가 처음 만나는 루틴을 소유 루틴으로 삼는다. 사이클과 누락을
방어하고 경로 전체를 메모한다.

## 3. 영역 간 관계 (AreaEdge)

같은 두 영역 사이의 같은 종류 관계를 하나로 합친 것.

| 필드 | 뜻 | 규칙 |
|---|---|---|
| `fromArea` / `toArea` | 양 끝 영역 | 서로 달라야 한다. 같으면 만들지 않는다(FR-002) |
| `kind` | `write` \| `read` \| `call` | 원본 관계 종류에서 파생 |
| `count` | 합쳐진 원본 관계 수 | 선 굵기의 근거(FR-003) |
| `viaTables` | 원인이 된 테이블 이름들 | `write`/`read`일 때. 사용자가 원인을 확인하는 근거(FR-007) |
| `viaRoutines` | 원인이 된 루틴 이름들 | `call`일 때 |

`write`/`read`/`call` 세 종류가 같은 영역 쌍에 모두 있으면 선은 3개가 된다(spec Edge Cases).

## 4. 테이블 소속 (TableOwnership)

| 필드 | 뜻 |
|---|---|
| `tableId` | 대상 테이블 |
| `ownerArea` | 주인 영역. 정할 수 없으면 `UNASSIGNED_AREA`('기타') |
| `writeCounts` / `readCounts` | 영역별 집계(진단·검증용) |

**판정 규칙(FR-005)** — 비교 하나. 계단식 예외를 두지 않는다.

```
영역마다 (writeCounts, readCounts) 를 만들고 사전식으로 가장 큰 영역이 주인이다.
가장 큰 영역이 유일하지 않으면 주인을 정하지 않고 UNASSIGNED_AREA 로 보낸다.
```

- 쓰기를 먼저 비교하므로 "데이터를 바꾸는 쪽이 주인"이라는 결정이 그대로 지켜진다.
- 쓰기가 전부 0이면 자동으로 읽기 수 비교로 넘어간다 — 읽기 전용 마스터를 위한 별도 조항이 없다.
- 동률을 임의로 깨지 않는다. 데이터가 주인을 말해주지 않으면 만들어내지 않는다(constitution IV).
- 결정론: 같은 입력에 항상 같은 출력. 집합 순회 순서에 의존하지 않는다.

**표시 규칙**

- 소속 영역이 접혀 있으면 테이블을 따로 그리지 않는다(FR-006, SC-004).
- 소속이 아닌 영역이 그 테이블을 읽거나 쓰면 `AreaEdge`가 된다(FR-007).
- 읽거나 쓰는 영역이 하나도 없으면 표시하지 않는다(FR-008).
- 테이블만 모으는 별도 구역을 만들지 않는다(FR-008a).

## 5. 펼침 상태 (ExpansionState)

| 필드 | 형태 | 규칙 |
|---|---|---|
| `expandedAreaIds` | 집합 | 사용자가 연 영역들 |
| `expandedModuleIds` | 집합 | 사용자가 연 모듈들 |
| `expandedRoutineId` | **단수 또는 없음** | 새 루틴을 열면 이전 것이 자동으로 닫힌다(FR-011) |

- 펼치기는 지목한 대상 하나에만 적용된다(FR-010).
- 전체를 한꺼번에 펴는 수단은 만들지 않는다(FR-012).
- 펼쳤을 때 드러나는 대상이 하나뿐인 층은 건너뛴다(FR-014).
- 루틴 내부는 어떤 상태에서도 캔버스에 올리지 않는다(FR-013).

## 6. 발견된 문제 (Finding)

| 종류 | 근거 | 출처 |
|---|---|---|
| 순환에 포함된 루틴 | `in_call_cycle == true` | 그래프에 저장됨 |
| 위험 루틴 | `risk_level == 'high'` (등급별 분리) | 그래프에 저장됨 |
| 주인이 아닌 영역이 쓰는 테이블 | §4 소속과 실제 쓰기 영역 비교 | 화면에서 계산 |

- 개수가 0이면 "0건"을 표시한다. 근거 속성 자체가 없으면 "정보 없음" 사유를 표시한다 — 둘을 구분한다
  (FR-024).
- 저장되지 않은 지표(거대 루틴 등)는 만들지 않는다(constitution IV).
- 순환 **고리**(어느 루틴끼리 도는지)는 저장돼 있지 않으므로 이번 범위에서 그리지 않는다.

## 7. 색 (RelationStyle)

색은 두 축의 함수다. 판정처는 `graphStyles.ts` 하나다.

| 축 | 값 |
|---|---|
| 색상 = 관계 종류 | `write` / `read` / `call` |
| 진하기 = 영역 통과 여부 | 넘음(뚜렷) / 안 넘음(흐림) |

- 굵기는 별개 축으로 `AreaEdge.count`를 나타낸다.
- 선 위 캡션은 한국어 표시명(`쓰기`/`읽기`/`호출`)이며, 표에 없는 타입은 원래 이름을 그대로 쓴다.
- 노드 자동 배색은 관계 색과 혼동될 수 있는 색 구역을 배정하지 않는다(FR-018).
