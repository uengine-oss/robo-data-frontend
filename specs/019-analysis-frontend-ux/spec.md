# Feature Specification: 분석 화면 UX 정합 — 노드패널 친절화 + 업로드 타겟언어 자동탐지

**Feature Branch**: `019-analysis-frontend-ux`

**Created**: 2026-06-19

**Status**: Draft

> 🔄 **식별부 정련 (2026-06-21, [023](../023-graph-render-node-detail/spec.md))**: FR-002 식별부(이름·논리명·종류·소속)를 **`buildIdentityRows` 단일 생성**으로 재구조 — **라인·분류·종류별(파라미터/반환/스키마/타입 등) 행 추가**, 경로는 `data/source/` 상대화, **소속 중 패키지는 식별 행에서 빼고 관계(연결) 섹션으로**. FR-001/003/004/005(보고서 순서·개요·원문·관계 묶음)·raw-id 미노출은 그대로.

**Input**: 019(라벨)·020(속성) 정체화 위에 올리는 **소비처 UX 정리**. ① 노드패널이 "이게 뭐고 어디 소속인지" 한눈에 들어오는 보고서형으로(현재 식별 빈약·관계 모호·raw-id 노출). ② 업로드 시 타겟언어 수동 선택칸이 antlr 자동감지와 중복 → 삭제.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 노드패널이 "보고서처럼" 읽힌다 (Priority: P1)

비개발자가 노드를 클릭하면 **이게 무엇이고(이름·논리명·종류) 어디에 속하는지(소속·패키지 경로)**가 맨 위에 깔끔히, 이어서 개요(전체 요약) → 원문 코드 → 관계 순으로 보인다. 더 이상 raw-id(콜론 합성 식별자)나 "멤버→"·"연결" 같은 모호한 표기가 보이지 않는다.

**Why this priority**: 노드패널은 사용자가 그래프를 이해하는 핵심 창구다. 현재 식별부가 빈약하고 관계 표기가 모호해 "이게 뭐지?" 혼란을 준다(사용자 직접 지적).

**Independent Test**: 재분석 그래프에서 파일·프로시저·구문·변수 노드를 각각 클릭 → 식별(이름+논리명+종류+소속) 명확, raw-id 노출 0, 이름 없는 구문은 `종류[시작라인]`, 관계가 읽기/쓰기/호출/소속으로 명확, 순서가 식별→개요→원문→관계.

**Acceptance Scenarios**:

1. **Given** 프로시저 노드, **When** 패널을 보면, **Then** 식별부에 이름·논리명·종류(PROCEDURE)·소속(파일/패키지 경로)가 분리 표시되고 raw-id는 없다.
2. **Given** 이름 없는 구문(SELECT) 노드, **When** 패널을 보면, **Then** `SELECT[라인]`으로 표시(콜론 합성 id 노출 0).
3. **Given** 루틴/구문 노드, **When** 개요·원문을 보면, **Then** 전체 요약(핵심 한 줄만 아님)과 원문 코드(code_text)가 보인다(파일 노드는 원문 없음 — 정상).
4. **Given** 노드의 관계, **When** 관계 영역을 보면, **Then** 읽기/쓰기/호출/소속/포함이 명확한 말로 묶여 보인다("멤버→"·"연결" 같은 모호 표기 0).
5. **Given** 020 속성, **When** 패널을 보면, **Then** notes 표시·signature 미표시(params·return_type)·위험은 risk_level/순환만(잡지표 없음).

---

### User Story 2 - 업로드 타겟언어는 자동으로 정해진다 (Priority: P2)

사용자가 코드를 업로드(또는 Electron 로컬 폴더 선택)하면 **언어를 직접 고를 필요 없이** 분석기가 자동 감지한다. 업로드 설정의 소스타입 수동 선택칸이 사라진다.

**Why this priority**: 파서가 두 입력 경로 모두에서 언어(Oracle/PostgreSQL 방언 포함)를 자동 감지하는데, 수동 선택칸이 남아 "Java 고정"처럼 보여 혼란을 준다(사용자 직접 지적). 수동칸은 중복이다.

**Independent Test**: .sql 폴더를 업로드 → 업로드 설정에 소스타입 수동 선택칸이 없고, 분석이 자동으로 올바른 전략(dbms)으로 진행된다. Java 프로젝트도 자동으로 framework.

**Acceptance Scenarios**:

1. **Given** 업로드 설정, **When** 열면, **Then** 소스타입 수동 선택 UI가 없다.
2. **Given** .sql/.java 업로드, **When** 분석하면, **Then** 자동 감지된 언어로 올바른 전략·화면(UML 탭 등)이 정해진다(회귀 0).

### Edge Cases

- **이름 없는 노드**: 식별 표시 = `종류[시작라인]`, raw-id 절대 노출 안 함.
- **속성 없는 노드**(빈값 미저장으로 키 부재): 해당 영역(원문·관계·위험)은 조용히 생략(에러·빈 박스 0).
- **자동감지 모호(순수 ANSI SQL)**: 분석기 기본값(oracle)으로 진행 — UI는 막지 않음.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 노드패널은 **식별 → 개요 → 원문코드 → 관계** 순의 보고서형으로 구성한다.
- **FR-002**: 식별부는 **이름 + 논리명(logical_name) + 종류(antlr type 라벨) + 소속/패키지 경로**를 분리 표시한다. **raw-id(콜론 합성 식별자)는 절대 노출하지 않는다**; 이름 없으면 `종류[시작라인]`.
- **FR-003**: 개요는 **전체 요약**(summary 전문)을 보인다(핵심 한 줄만 자르지 않음).
- **FR-004**: 루틴/구문 노드는 **원문 코드(code_text)** 를 보인다. 파일·그릇처럼 원문이 없는 노드는 원문 영역을 생략한다.
- **FR-005**: 관계는 **읽기/쓰기/호출/소속/포함** 등 사람이 읽는 묶음으로 표시한다. "멤버→"·"연결" 같은 모호 표기를 제거한다.
- **FR-006**: 020 속성 모델을 반영한다 — `notes` 표시, `signature` 미표시(있으면 `params`·`return_type`), 위험은 `risk_level`(+순환 `in_call_cycle`)만(loc·god·fan 등 잡지표 표시 없음).
- **FR-007**: 업로드 설정의 **소스타입 수동 선택 UI를 제거**한다. 언어는 분석기 자동 감지(파싱 시 detected)에 맡긴다 — 두 입력 경로(브라우저 업로드/로컬 폴더) 공통.
- **FR-008**: 수동 UI 제거가 분석 전략·화면(UML 탭 등) 동작을 깨지 않아야 한다(회귀 0 — 파싱 자동감지가 sourceType을 채움).
- **FR-009**: 019 라벨·020 속성 정체화 결과를 전제로 하며 되돌리지 않는다.

### Key Entities *(표시 데이터)*

- **노드 식별**: 이름 · 논리명 · 종류(라벨) · 소속(파일/패키지 경로) — raw-id 제외.
- **노드 본문**: 개요(summary 전문) · 원문(code_text) · notes.
- **노드 관계**: 읽기(READS)/쓰기(WRITES)/호출(CALLS)/소속(BELONGS_TO)/포함(HAS_MEMBER) 등 의미 묶음.
- **위험 표시**: risk_level · in_call_cycle (루틴).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 노드패널에서 raw-id(콜론 합성 식별자) 노출이 **0건**(이름 없으면 `종류[라인]`).
- **SC-002**: 식별부에 이름·논리명·종류·소속이 분리 표시되어, 비개발자가 "무엇·어디 소속"을 한눈에 파악한다.
- **SC-003**: 개요(전문)·원문코드·관계가 보고서 순서로 보이고, "멤버→"·"연결" 모호 표기가 **0건**.
- **SC-004**: 업로드 설정에 소스타입 수동 선택 UI가 **0건**이며, .sql/.java 분석이 자동 전략으로 정상 동작(회귀 0).
- **SC-005**: 020 잡지표(loc·god·fan)·signature가 패널에 **표시 0**, notes·risk_level 표시 정상.

## Assumptions

- 대상 = `robo-data-frontend`(노드패널 카드·업로드 모달). 백엔드 무변경(019·020 위).
- 검증은 단위테스트가 아니라 재분석 그래프로 Playwright 스크린샷·동작 확인([[manual]] §3 — NVL 캔버스는 헤드리스 한계, 패널·모달·트리는 렌더).
- antlr 자동감지(detected 이벤트 + LanguageDetector 방언 점수화)가 두 경로 공통으로 sourceType을 채운다(검증 완료).
- 노드 종류·소속·관계·논리명 데이터는 019·020 산출 그래프에서 온다.
