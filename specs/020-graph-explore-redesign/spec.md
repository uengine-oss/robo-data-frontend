# Feature Specification: 그래프 탐색 UX 재설계 — 보기·필터·isolate·친화 콘솔

**Feature Branch**: `main` (전용 브랜치 미생성)

**Created**: 2026-06-19

**Status**: Draft

**Input**: User description: "분석가가 코드 그래프를 혼란 없이 탐색 — 보기모드(장면 프리셋)·필터(종류 끄고켜기)·isolate(이것만)·친화 콘솔의 역할을 명확히 분리. 영역(구조 묶기)과 협력군집(CALL 군집)을 분리, 모듈간은 CALL+테이블 둘 다, 건강은 R/W도 표시."

## 배경 (현재 혼란 — 사용자 피드백으로 확정)

코드 그래프 화면의 "보기 모드"가 여러 개념을 섞어 혼란을 준다:
- **"영역 보기"가 실제로는 CALL 군집(Leiden)** 이다. 사람들은 "영역"을 *파일/모듈 단위 묶기*로 기대하는데, 호출 기반이라 호출 적은 코드에선 빈약·"뚝뚝 끊김".
- **오버뷰 패널에서 노드 종류를 클릭하면 "필터(빼기)"** 라, 빈 캔버스에서 누르면 "매치되는 노드 없음"이 떠 혼란("보여달라는데 숨김으로 동작").
- **관계 종류는 끄고/켤 수 없다**(클릭하면 색 편집만).
- **모듈간 상호작용**은 모듈↔테이블(R/W)만 보여주고 모듈↔모듈(호출)은 빠져 있다.
- **건강 보기**는 위험도 색은 칠하나 화면 관계가 CALL뿐이라(테이블 미표시) 위험 루틴들이 외딴섬처럼 흩어진다.
- **콘솔**이 기술용어 위주라 "잘 처리되는지" 직관적으로 안 와닿는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 보기·필터·isolate 3축이 명확히 분리된다 (Priority: P1) 🎯 MVP

분석가가 화면 상단에서 **"보기 ▾"(큰 장면 프리셋)** 와 **"필터 ▾"(노드·관계 종류 끄고/켜기)** 를 나란히 쓰고, **오버뷰 패널의 칩을 클릭하면 "그것만 보기"(isolate)** 가 된다. 세 동작의 역할이 겹치지 않아 "필터인데 빈 화면" 같은 모순이 사라진다.

**Why this priority**: 모든 혼란의 뿌리. 이 상호작용 모델이 서면 나머지 보기모드 개선이 그 위에 깔끔히 얹힌다.

**Independent Test**: 빈 캔버스에서 오버뷰의 TABLE 칩을 클릭 → 테이블만 뜬다(빈 화면/경고 X). 필터 ▾에서 READS를 끄면 읽기 관계가 사라진다. 보기 ▾와 필터 ▾가 동시에 적용된다.

**Acceptance Scenarios**:

1. **Given** 빈 캔버스, **When** 오버뷰에서 노드 종류 칩(예: TABLE)을 클릭, **Then** 그 종류 노드가 캔버스에 **나타난다**(숨김/경고 아님).
2. **Given** 노드가 있는 캔버스, **When** 다른 종류 칩을 클릭, **Then** "그것만" 보인다(isolate). 전체(`*`)를 누르면 원복.
3. **Given** 어떤 보기 모드든, **When** 필터 ▾에서 노드/관계 종류를 끄고/켜면, **Then** 그 종류만 즉시 숨겨지거나 보인다(여러 개 동시 가능).
4. **Given** 보기 ▾로 장면을 고른 상태, **When** 필터 ▾로 특정 관계를 끄면, **Then** 둘이 **동시 적용**된다(서로 안 덮어씀).
5. **Given** 읽기만/쓰기만, **When** 필터를 보면, **Then** 그 옵션이 **필터 ▾(관계)** 에 있다(보기 드롭다운엔 없다 = 보기는 프리셋 전용).

---

### User Story 2 - "영역(구조)"과 "협력 군집"이 분리된다 (Priority: P2)

분석가가 **"영역(구조)"** 보기를 켜면 노드가 **파일/모듈 단위로 동그란 영역에 묶이고 영역 이름 = 파일/모듈명**으로 보인다(모든 노드가 소속이 있어 항상 꽉 참). 호출 기반의 옛 "영역 보기"는 **"협력 군집"** 으로 이름이 바뀌고, 군집이 빈약하면 사유를 알려준다.

**Why this priority**: "영역"의 의미를 바로잡아 사용자 기대와 일치시킨다. P1(상호작용) 다음.

**Independent Test**: "영역(구조)" 보기 → 파일/모듈별 색 영역 + 이름이 보이고 끊김 없음. "협력 군집" 보기 → CALL 군집이 보이고, 호출 적으면 "내부 호출 N개라 군집이 작습니다" 안내가 뜬다.

**Acceptance Scenarios**:

1. **Given** 분석된 그래프, **When** "영역(구조)" 보기를 켜면, **Then** 노드가 파일/모듈 단위로 색 영역에 묶이고 **영역 이름 = 파일/모듈명**, 빈 영역/끊김 없음.
2. **Given** 호출이 적은 코드, **When** "협력 군집" 보기를 켜면, **Then** CALL 군집이 보이고 **"호출이 적어 군집이 작습니다(내부 호출 N개)"** 안내가 표시된다.
3. **Given** 옛 "영역 보기"를 기억하는 사용자, **When** 보기 메뉴를 열면, **Then** 호출 군집은 **"협력 군집"** 으로, 구조 묶기는 **"영역(구조)"** 로 **이름이 구분**되어 있다.

---

### User Story 3 - 모듈간·건강 보기가 풍부해진다 (Priority: P3)

**모듈간 상호작용**이 모듈↔테이블(R/W) 뿐 아니라 **모듈↔모듈(호출 집계)** 도 함께 보여준다. **건강** 보기가 위험도 색에 더해 **테이블 접근(R/W)도 같이 그려** 위험 루틴이 어느 테이블을 건드리는지 보이고 외딴섬이 줄어든다.

**Why this priority**: 분석 가치를 높이는 개선. 핵심 상호작용/개념 정리(P1·P2) 다음.

**Independent Test**: 모듈간 보기 → 모듈끼리 호출선 + 모듈↔테이블선이 함께 보인다. 건강 보기 → 위험색 루틴 + 그 루틴의 테이블 R/W선이 보인다(흩어짐 감소).

**Acceptance Scenarios**:

1. **Given** 모듈간 보기, **When** 모듈 A의 루틴이 모듈 B의 루틴을 호출하면, **Then** **모듈 A→B 호출선**이 합성되어 보인다(모듈↔테이블선과 함께).
2. **Given** 건강 보기, **When** 위험 루틴이 테이블을 R/W 하면, **Then** 그 **테이블과 R/W 관계가 함께** 그려져 루틴이 외딴섬이 아니다.
3. **Given** 모듈간/건강 보기, **When** 필터 ▾에서 CALL이나 R/W를 끄면, **Then** 해당 관계만 숨겨진다(보기는 유지).

---

### User Story 4 - 콘솔이 "잘 처리되고 있구나"를 전한다 (Priority: P4)

분석 중 콘솔이 **사람 말 + 진행감**으로 흐른다. 무엇을 얼마나 했는지("테이블 16개 읽음 → 코드 461개 분석 중") 중심으로, 기술용어는 숨기고, 완료는 ✅·진행은 현재 대상 표시.

**Why this priority**: 신뢰감·안심을 주는 개선. 기능 정합(P1~P3) 후 마감 단계.

**Independent Test**: 분석을 돌리면 콘솔이 단계별 사람말로 끊김 없이 흐르고, 기술 토큰(node_event 등)이 노출되지 않는다.

**Acceptance Scenarios**:

1. **Given** 분석 진행 중, **When** 콘솔을 보면, **Then** 단계별 진행이 **사람 말**로 누적되고("…분석 중 N/M") 멈춘 듯 보이지 않는다.
2. **Given** 콘솔 메시지, **When** 읽으면, **Then** 내부 기술용어(이벤트 타입·step 함수명)가 표면에 안 보인다.

---

### User Story 5 - 데이터 흐름 보기 + 데이터 부족 안내 (Priority: P5, 옵션)

**테이블 흐름** 보기(테이블 + DML 노드 + R/W만)로 데이터 흐름에 집중할 수 있고, 어떤 보기든 결과가 빈약하면 **사유를 안내**한다(조용한 실패 금지).

**Why this priority**: 부가 가치. 핵심 다 된 뒤.

**Independent Test**: "테이블 흐름" 보기 → 테이블·DML·R/W만 보인다. 데이터 부족 시 안내 문구가 뜬다.

**Acceptance Scenarios**:

1. **Given** 분석된 그래프, **When** "테이블 흐름" 보기를 켜면, **Then** 테이블·DML 구문·R/W 관계만 보인다.
2. **Given** 결과가 빈약한 보기, **When** 그 보기를 켜면, **Then** **빈 화면 대신 사유 안내**가 뜬다.

---

### Edge Cases

- 필터로 모든 종류를 다 끄면? → 빈 캔버스 + "모두 숨김 — 종류를 켜세요" 안내(혼란 방지).
- 보기 모드가 노드를 제한했는데(예: 건강=루틴) 필터로 다른 종류를 켜면? → 그 종류가 추가로 로드된다(보기모드의 제한보다 사용자 명시 선택 우선) — 단 일관된 규칙으로.
- isolate(이것만) 후 다시 전체로? → 오버뷰의 `*`(전체) 칩으로 원복.
- 영역(구조)에서 한 파일에 노드가 1개뿐이면? → 1개짜리도 영역으로 감싸 이름 표시(구조는 항상 소속 보장).
- 협력 군집이 0개(호출 전무)면? → 빈 화면 대신 "내부 호출이 없어 협력 군집을 만들 수 없습니다" 안내.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: "보기 ▾"는 **상호배타 보기모드(프리셋)** 만 담는다(하나만 활성).
- **FR-002**: "필터 ▾"는 **노드 종류 + 관계 종류**를 각각 **다중 토글(끄고/켜기)** 한다. 보기 모드와 **동시 적용**(직교).
- **FR-003**: 관계 종류를 **끄고/켤 수 있어야** 한다(현재 없음).
- **FR-004**: 오버뷰 패널의 노드 종류 칩 클릭은 **"이것만 보기"(isolate)** 이며, **빈 캔버스에서도 해당 종류를 로드해 표시**한다(숨김/경고 금지).
- **FR-005**: 읽기만/쓰기만 관계 필터는 **필터 ▾(관계)** 에 위치한다(보기 드롭다운에 두지 않는다).
- **FR-006**: **"영역(구조)"** 보기는 노드를 **파일/모듈 단위**로 영역에 묶고 **영역 이름 = 파일/모듈명**으로 표시한다(모든 노드 소속 보장 → 끊김 없음).
- **FR-007**: 기존 호출 기반 군집 보기는 **"협력 군집"** 으로 명명되고 영역(구조)과 별개 보기로 공존한다.
- **FR-008**: **모듈간 상호작용**은 **모듈↔모듈(호출 집계) + 모듈↔테이블(R/W)** 을 함께 표시한다.
- **FR-009**: **건강** 보기는 위험도 색에 더해 **루틴의 테이블 R/W(테이블 노드 포함)** 를 함께 표시한다.
- **FR-010**: 군집/영역/관계 결과가 빈약하면 **사유를 안내**한다(빈 화면 침묵 금지).
- **FR-011**: 콘솔은 분석 진행을 **사람 말 + 진행감**으로 표시하고 내부 기술용어를 표면에 노출하지 않는다.
- **FR-012**: (옵션) **테이블 흐름** 보기는 테이블·DML 노드·R/W만 표시한다.
- **FR-013**: 회귀 금지 — 드래그-드롭, 1-hop 확장, 노드 상세 패널, 보기모드 색상(크래시 0), 라이브 스트림이 그대로 동작한다.

### Key Entities *(include if feature involves data)*

- **보기 모드(프리셋)**: 기본·영역(구조)·협력 군집·모듈간·건강·테이블 흐름. 한 번에 하나.
- **표시 필터**: 노드 종류 집합 + 관계 종류 집합(각 다중 on/off). 보기와 직교.
- **isolate 선택**: 오버뷰 칩 클릭으로 "그 종류만" 표시.
- **그룹(영역)**: 구조(파일/모듈) 또는 협력(CALL 군집) 기준으로 노드를 감싸는 색 영역 + 이름.
- (전제 데이터, 변경 없음) 노드(라벨·component_id·risk_level)·관계(CALLS·READS·WRITES·HAS_MEMBER·PARENT_OF).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 빈 캔버스에서 오버뷰 칩을 클릭하면 **100% 그 노드가 표시**된다("매치 없음" 0).
- **SC-002**: 관계 종류를 **끄고/켤 수 있다**(현재 불가 → 가능).
- **SC-003**: "영역(구조)" 보기에서 **모든 노드가 어떤 영역에 소속**되어 표시된다(미소속/끊김 0).
- **SC-004**: 보기 메뉴에서 "영역(구조)"과 "협력 군집"이 **다른 이름으로 구분**된다.
- **SC-005**: 모듈간 보기에서 **모듈↔모듈 호출선과 모듈↔테이블선이 둘 다** 나타난다.
- **SC-006**: 건강 보기에서 위험 루틴이 **테이블과 연결되어** 외딴섬 비율이 줄어든다.
- **SC-007**: 결과 빈약 시 **빈 화면 대신 사유 안내**가 100% 표시된다.
- **SC-008**: 콘솔에 내부 기술용어(이벤트 타입·step 함수명)가 **표면 노출 0**.
- **SC-009**: 회귀 0 — 기존 탐색·스트림·색상(크래시 0)이 유지된다.

## Assumptions

- 필요한 데이터(CALLS·READS·WRITES·HAS_MEMBER·PARENT_OF·component_id·risk_level)는 **이미 그래프에 존재**한다(분석 완주 시). 노드/관계/속성 모델은 변경하지 않는다.
- "영역(구조)" 묶기는 파일 단위를 기본으로 하되, 파일 위 패키지/모듈 단위 묶기로 확장 가능(plan에서 결정).
- 모듈간 모듈↔모듈 집계는 기존 모듈↔테이블 집계와 **같은 방식**(루틴 관계를 모듈로 끌어올림)을 재사용한다.
- spec 022(스트림 라이브·카운트·색상 hsl→hex 크래시수정)는 이 스펙의 **전제**이며 중복하지 않는다. 016/018(그래프 보기/탐색) 중 보기모드·필터 부분은 본 스펙이 **대체(supersede)** 한다.

## 범위 밖 (Out of Scope)

- 노드 라벨/속성/식별자 모델 변경(017/019/020 백엔드 모델 불변).
- 새 분석 단계 추가·분석 알고리즘 변경(군집은 기존 Leiden 그대로, 표시만 재구성).
- 의미적 분석(RULE/EXAMPLE 흐름) 보기 — 별도 후속 스펙 후보.
