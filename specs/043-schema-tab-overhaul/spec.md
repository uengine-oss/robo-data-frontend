# Feature Specification: 스키마 탭 전면 고도화 (소스뷰 근본수정 + 버그정리 + UI 일관화)

**Feature Branch**: `043-schema-tab-overhaul`

**Created**: 2026-06-28

**Status**: Draft

**Input**: 스키마 탭은 거의 미작업 상태로 여러 문제가 있다. (1) 테이블 참조에서 함수/프로시저를 누르면 코드 패널이 "파일 내용을 찾을 수 없습니다 / N/A"만 뜬다(데스크톱 모드엔 브라우저 업로드가 없어 구조적으로 깨짐). (2) 참조의 ✓ "방문 표시"가 안 사라지고 혼란만 준다. (3) 닫기(X) 버튼·보기 버튼·정렬 등 UI가 컴포넌트마다 제각각이라 일관성·편의성이 낮다. 이 세 축을 근본수정·일관화한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 영속 그래프에서도 실제 소스 코드를 본다 (Priority: P1)

데스크톱(폴더 선택) 모드나 이미 분석된 그래프를 불러온 상태에서, 스키마 탭 "테이블 참조" 팝업의 함수/프로시저를 클릭하면 **실제 원본 코드**가 오른쪽 패널에 해당 줄로 열린다. 더 이상 가짜 "// 파일 내용을 찾을 수 없습니다 / N/A" 텍스트가 코드인 양 뜨지 않는다. 원본이 정말 없는 경우에만 **정직한 안내**(코드가 아님이 명확한 빈 상태)를 보여준다.

**Why this priority**: 현재 코드뷰는 "브라우저가 업로드한 파일을 메모리에 들고 있다"는 전제 위에 있어, 업로드가 없는 데스크톱/영속 그래프에선 항상 깨진다. 제품의 주 사용 흐름에서 핵심 기능이 죽어 있으므로 최우선.

**Independent Test**: 업로드 없이 기존 그래프를 불러온 상태에서 참조의 함수를 클릭 → 실제 소스가 해당 줄로 표시되는지 확인(원본 파일이 디스크에 있을 때). 디스크에도 없는 경로면 가짜 코드가 아니라 정직한 "소스 없음" 안내가 뜨는지 확인.

**Acceptance Scenarios**:

1. **Given** 분석된 그래프가 로드돼 있고 원본 소스가 디스크(소스 루트)에 존재, **When** 테이블 참조의 함수/프로시저를 클릭, **Then** 오른쪽 소스 패널에 실제 파일 내용이 해당 줄 중심으로 표시된다.
2. **Given** 노드가 가리키는 원본 파일이 디스크에 없음, **When** 참조를 클릭, **Then** 가짜 "// …" 코드가 아니라 "원본 소스를 찾을 수 없음"이 명확한 정직한 상태가 표시된다.
3. **Given** 브라우저 업로드가 전혀 없는 세션, **When** 참조 코드뷰를 사용, **Then** 동작이 업로드 여부와 무관하게 동일하다(`uploadedFiles` 의존 없음).

---

### User Story 2 - 혼란 주는 표시·죽은 동작 제거 (Priority: P2)

테이블 참조 팝업에서 항목을 클릭해도 의미 없는 ✓ "방문 표시"가 영구히 쌓이거나 다른 테이블로 누수되지 않는다(표시 자체 제거). 사용자가 "체크가 안 사라진다"고 느끼던 혼란이 사라진다.

**Why this priority**: 기능적 효과가 없고 토글로 오해만 부르는 잔여 상태. 제거가 곧 정리(코드 감소).

**Independent Test**: 참조를 여러 번 클릭/다른 테이블 참조를 열어도 ✓ 마커가 나타나지 않음을 확인.

**Acceptance Scenarios**:

1. **Given** 테이블 참조 팝업, **When** 항목을 클릭, **Then** ✓ 방문 표시가 생기지 않는다.
2. **Given** A 테이블 참조를 보고 닫은 뒤 B 테이블 참조를 연다, **When** 팝업을 본다, **Then** 이전 클릭 흔적이 남지 않는다.

---

### User Story 3 - 일관되고 편한 스키마 UI (Priority: P2)

스키마 탭의 닫기(X)·제거 버튼이 모든 팝업/패널/모달에서 같은 모양·위치로 통일된다. 테이블 목록의 "상위 10개"·"전체 테이블 보기"가 그래프 탭처럼 **하나의 보기모드 컨트롤**로 합쳐지고, 논리명/물리명 토글의 중복 표시가 정리된다. '캔버스에 있는 테이블' 칩의 빨간 X 정렬 등 눈에 띄는 어긋남이 정돈된다.

**Why this priority**: 사용자가 직접 지목한 일관성·편의성 문제. 기능 흐름과 독립적으로 체감 품질을 크게 올린다.

**Independent Test**: 모든 닫기 버튼이 동일 스타일인지, 보기 컨트롤이 단일화됐는지, 칩 X가 정렬됐는지 스크린샷으로 확인.

**Acceptance Scenarios**:

1. **Given** 스키마 탭의 어떤 팝업/패널/모달이든, **When** 닫기 버튼을 본다, **Then** 동일한 아이콘·크기·호버 스타일이다.
2. **Given** 좌측 테이블 사이드바, **When** 테이블 보기 컨트롤을 본다, **Then** "상위 10개/전체"가 단일 보기모드 컨트롤로 제공되고 논리명/물리명 토글이 중복 없이 한 곳에 있다.
3. **Given** '캔버스에 있는 테이블' 칩, **When** 제거(X) 버튼을 본다, **Then** 정렬·간격·호버가 다른 제거 칩과 일관된다.

---

### Edge Cases

- 소스 엔드포인트가 소스 루트 밖 경로를 받으면 거부(보안: 경로 이탈 차단)하고 프론트는 정직한 빈 상태로 처리.
- 참조 노드가 절대 file_path를 안 가진 경우(프로시저 참조)에도 경로를 확보해 코드뷰가 동작해야 한다.
- 보기모드 전환 중/대량 테이블 로드 중 로딩 상태가 보여야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 소스 코드뷰는 브라우저 업로드 파일이 아니라 **백엔드가 디스크에서 읽어 주는 원본 소스**로 동작해야 한다(웹·데스크톱 공통, `uploadedFiles` 의존 제거).
- **FR-002**: 백엔드 소스 엔드포인트는 **소스 루트 밖 경로 접근을 차단**해야 한다(경로 이탈 보안).
- **FR-003**: 원본을 못 읽는 경우, 코드처럼 보이는 가짜 텍스트 대신 **명확한 "소스 없음" 상태**를 표시해야 한다.
- **FR-004**: 프로시저 참조든 프레임워크 참조든 **절대 파일 경로를 확보**해 동일하게 코드뷰가 열려야 한다.
- **FR-005**: 참조 ✓ "방문 표시" 기능을 **제거**한다(상태·렌더·스타일 일체).
- **FR-006**: 스키마 탭의 모든 닫기(X)·제거 버튼은 **단일 공통 스타일/패턴**으로 통일한다.
- **FR-007**: "상위 10개"·"전체 테이블 보기"를 **단일 보기모드 컨트롤**로 통합하고, 논리명/물리명 토글의 중복 렌더를 제거한다.
- **FR-008**: '캔버스에 있는 테이블' 등 목록 칩의 제거(X) 정렬·간격·호버를 일관화한다.
- **FR-009**: 기존 동작 회귀 0 — 관계 추가/삭제, 테이블 추가, 논리명/물리명 전환, 참조 조회 등 기존 기능은 그대로 동작해야 한다.

### Key Entities

- **소스 파일(원본 코드)**: 디스크의 `소스루트/<타깃>/...`에 절대경로로 존재. 노드의 `file_path`(절대)로 식별.
- **테이블 참조(reference)**: 프로시저/프레임워크가 테이블을 읽고/쓰는 관계. 이름·접근유형·줄번호·파일경로 메타데이터.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 업로드 없이 그래프만 로드한 상태에서 참조 클릭 시 실제 소스가 표시된다(원본이 디스크에 있을 때 성공률 100%).
- **SC-002**: 어떤 경우에도 코드 패널에 가짜 "// 파일 내용을 찾을 수 없습니다" 텍스트가 코드로 표시되지 않는다(0건).
- **SC-003**: 참조 ✓ 마커 노출 0건.
- **SC-004**: 스키마 탭 닫기 버튼 스타일 종류가 1종으로 수렴(현재 5종 → 1종).
- **SC-005**: 테이블 보기 컨트롤이 단일화되고 논리명/물리명 토글 중복 렌더 0.

## Assumptions

- 분석된 원본 소스는 디스크(소스 루트)에 남아 있으며 노드 `file_path`가 절대경로다(analyzer가 그렇게 박음). 재분석은 하지 않는다.
- 소스 서빙 엔드포인트는 analyzer(5502)에 두고 gateway(9000)를 통해 프론트가 호출한다.
- 구문 강조·펼침 애니메이션·키보드 네비·토스트 등은 이번 범위 밖(후속 todo).
