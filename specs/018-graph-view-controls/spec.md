# Feature Specification: 코드분석 그래프 화면 — 보기 컨트롤·노드패널 구조 정리

**Feature Branch**: `018-graph-view-controls`

**Created**: 2026-06-18

**Status**: Draft

**Input**: User description: 코드분석 그래프 화면(GraphTab)의 상단 툴바·보기·노드패널 구조 정리 — 상단 버튼 6개 일렬 → 정돈, 보기 모드 무한 확장 대비, 보기별 세부옵션 둘 곳 마련, 레전드 중복 제거. **최우선 = 사용자가 쓰기 편할 것.**

## 개요 *(맥락)*

코드분석 화면은 좌측 Navigator(트리) + 가운데 그래프 캔버스 + 우측 노드패널(선택 노드 상세 / 비선택 시 Node labels·Relationship types 레전드)로 구성된다. 현재 캔버스 위에 **버튼 6개가 일렬로 떠 있다**: 물리명/논리명 토글, 모듈간 상호작용, 영역 보기, 건강 보기, 읽기만, 쓰기만. 

문제: ① 종류가 다른 컨트롤(표시토글·보기전환·관계필터)이 한 줄에 뒤섞여 지저분하고 캔버스와 시각적으로 겹친다. ② **보기 모드가 앞으로 계속 추가**될 예정인데 일렬 버튼은 확장 불가(곧 넘침). ③ 각 보기마다 **세부옵션**(예: "테이블 관계 보기"의 DB링크만/읽기만/쓰기만)이 생길 수 있는데 둘 자리가 없다. ④ 레전드(Node labels·Relationship types)가 진행패널(도킹 시)과 우측 노드패널 **두 곳에 중복**으로 그려진다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 상단이 깔끔하고, 보기는 한 곳에서 고른다 (Priority: P1)

분석가가 그래프 화면을 열면, 캔버스 위가 버튼으로 어수선하지 않고 "이름 표시 토글"과 "보기 선택" 단 두 가지만 보인다. 어떤 보기로 볼지는 한 곳(보기 선택)에서 고른다.

**Why this priority**: 화면 첫인상의 어수선함이 핵심 통증이며, 보기가 늘어날수록 악화된다. 이걸 해결하지 못하면 나머지는 의미가 없다.

**Independent Test**: 그래프 화면에서 상단에 보이는 컨트롤이 [이름 토글] + [보기 선택] 둘뿐이고, 보기 선택을 열면 현재의 모든 보기(모듈간 상호작용/영역/건강)가 목록으로 나오며 하나를 고르면 적용됨을 확인한다.

**Acceptance Scenarios**:

1. **Given** 그래프 화면, **When** 화면을 열면, **Then** 캔버스 위 컨트롤은 이름 표시 토글과 보기 선택 두 가지만 보이고 캔버스를 가리지 않는다.
2. **Given** 보기 선택을 연 상태, **When** 보기 하나(예: 모듈간 상호작용)를 고르면, **Then** 그 보기가 적용되고 현재 활성 보기가 무엇인지 화면에 표시된다.
3. **Given** 새 보기 모드가 추가된 상황, **When** 보기 선택을 열면, **Then** 상단 레이아웃이 깨지거나 넘치지 않고 목록에 새 항목만 추가되어 나타난다.

---

### User Story 2 - 고른 보기의 세부옵션을 한 자리(노드패널)에서 조정한다 (Priority: P1)

분석가가 어떤 보기를 고르면, 그 보기에서만 의미 있는 세부옵션(예: 테이블 관계 보기의 "읽기만/쓰기만/DB링크만")이 **우측 노드패널의 일정한 자리**에 나타나 거기서 조정한다. 보기를 바꾸면 그 자리에 새 보기의 옵션이 들어온다.

**Why this priority**: 세부옵션이 상단 버튼으로 흩어지면 곧 다시 어수선해진다. "보기는 위에서 고르고, 그 보기의 조정은 노드패널에서" 라는 일관된 위치 규칙이 확장성과 학습 용이성의 핵심이다.

**Independent Test**: "테이블 관계" 같이 옵션이 있는 보기를 고르면 노드패널 상단에 그 옵션(읽기만/쓰기만/DB링크만)이 나타나고, 옵션을 켜고 끄면 그래프에 반영되며, 다른 보기로 바꾸면 옵션이 그 보기 것으로 교체됨을 확인한다.

**Acceptance Scenarios**:

1. **Given** 세부옵션이 있는 보기를 고른 상태, **When** 노드패널을 보면, **Then** 패널 상단에 "활성 보기 + 그 보기의 옵션"이 표시된다.
2. **Given** 노드패널의 세부옵션, **When** 옵션(예: 읽기만)을 켜면, **Then** 그래프에 즉시 반영되고 다시 끄면 원래대로 돌아온다.
3. **Given** A 보기의 옵션이 보이는 상태, **When** B 보기로 바꾸면, **Then** A의 옵션은 사라지고 B의 옵션으로 교체된다(잔여 옵션 0).
4. **Given** 세부옵션이 없는 보기, **When** 그 보기를 고르면, **Then** 옵션 영역은 비거나 숨고 레전드만 보인다.

---

### User Story 3 - 같은 정보(레전드)는 한 곳에만 (Priority: P2)

분석가가 노드 라벨/관계 종류 레전드를 볼 때, 같은 레전드가 두 군데 중복으로 뜨지 않고 한 곳(노드패널)에만 있다. 진행 패널은 분석 진행률만 보여준다.

**Why this priority**: 중복은 혼란·시선분산의 원인이며 구조를 "더럽게" 만드는 직접 요인. 단 P1(보기 구조)보다는 후순위.

**Independent Test**: 분석 진행 중/후 모두에서 Node labels·Relationship types 레전드가 화면에 한 번만 나타남을 확인한다.

**Acceptance Scenarios**:

1. **Given** 분석 진행 중(진행 패널 표시), **When** 화면을 보면, **Then** 레전드는 노드패널에만 있고 진행 패널엔 진행률만 있다.
2. **Given** 분석 완료 상태, **When** 노드패널을 보면, **Then** 레전드가 한 곳에서 정상 표시된다.

---

### User Story 4 - 트리·네비게이터가 한눈에 읽힌다 (Priority: P2)

분석가가 좌측 Navigator 트리를 볼 때, 펼치기/접기 동작이 직관적인 아이콘으로 명확하고, 네비게이터를 접고 펴는 것이 자연스러운 토글로 되며, 트리 들여쓰기·상태 표시 점 크기가 빽빽하지 않게 읽힌다.

**Why this priority**: 가독성 개선이지만 핵심 구조(P1)보다는 후순위. 단 매일 보는 트리라 체감 크다.

**Independent Test**: 모두 펼치기/모두 접기 버튼의 아이콘만 보고 기능을 맞힐 수 있고, 네비게이터를 토글로 접었다 펼 수 있으며, 트리 계층이 들여쓰기로 명확히 구분됨을 확인한다.

**Acceptance Scenarios**:

1. **Given** Navigator 헤더, **When** 모두 펼치기/접기 아이콘을 보면, **Then** 비개발자도 어느 쪽이 펼치기·접기인지 즉시 구분한다.
2. **Given** 네비게이터가 열린 상태, **When** 토글을 누르면, **Then** 접히고, 접힌 상태에서 다시 누르면 펴진다(상태가 명확히 보임).
3. **Given** 깊은 트리, **When** 트리를 보면, **Then** 계층별 들여쓰기와 상태 점 크기가 빽빽하지 않고 단계가 구분된다.

---

### User Story 5 - 노드 색이 서로 안 겹쳐 구분된다 (Priority: P2)

분석가가 노드 라벨이 20종 이상인 그래프를 볼 때, 라벨별 색이 기본적으로 서로 최대한 다르게 배정되어 비슷한 색끼리 헷갈리지 않는다.

**Why this priority**: 라벨이 많아 색 충돌이 실재하나, 의미 전달(라벨 텍스트)은 유지되므로 P2.

**Independent Test**: 라벨이 많은 분석 결과에서 인접/유사 라벨의 색이 육안으로 구분되는지, 색 충돌이 기본값에서 최소화되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 라벨 20종 이상 그래프, **When** 화면을 보면, **Then** 라벨 색이 기본값으로 서로 구분되게(유사색 인접 최소) 배정된다.
2. **Given** 색 배정, **When** 같은 분석을 다시 보면, **Then** 같은 라벨엔 같은 색이 안정적으로 유지된다(재현성).

### Edge Cases

- **보기 모드가 매우 많아질 때**: 보기 선택 목록이 길어져도 상단 레이아웃은 불변(목록 내부에서 스크롤/그룹). 상단 버튼이 늘지 않는다.
- **세부옵션이 많은 보기**: 노드패널 옵션 영역이 길어지면 그 영역만 스크롤되고 레전드는 계속 접근 가능.
- **노드/관계 선택 중**: 노드패널이 "선택 상세"를 보일 때와 "보기 옵션+레전드"를 보일 때의 전환이 명확해야 한다(둘이 안 섞임).
- **분석 진행 중**: 진행 패널이 떠 있어도 보기 선택·노드패널 옵션은 정상 동작.
- **이름 토글(물리/논리)**: 보기·옵션과 독립적으로 항상 동작(특정 보기에서 사라지지 않음).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 캔버스 위 상단 컨트롤은 **이름 표시 토글(물리명/논리명)** 과 **보기 선택** 두 가지로 한정해야 한다. 그 외 보기·필터 버튼을 상단에 일렬로 두지 않는다.
- **FR-002**: 상단 컨트롤은 캔버스 콘텐츠를 가리지 않는 **고정 위치 띠**로 배치하고, 캔버스 위에 떠다니며 겹치지 않아야 한다.
- **FR-003**: 모든 보기 모드(모듈간 상호작용·영역 보기·건강 보기·향후 추가분)는 **보기 선택 한 곳**에서 고를 수 있어야 하며, 새 보기 추가 시 상단 레이아웃 변경 없이 목록 항목만 늘어야 한다.
- **FR-004**: 현재 **활성 보기**가 무엇인지 사용자가 항상 알 수 있어야 한다.
- **FR-005**: 보기별 **세부옵션**(예: 읽기만/쓰기만/DB링크만)은 **우측 노드패널의 일정한 자리**(비선택 상태일 때)에서 조정되어야 하며, 상단 버튼으로 두지 않는다.
- **FR-006**: 보기를 전환하면 노드패널 세부옵션은 **그 보기의 것으로 교체**되고 이전 보기의 옵션 잔여물이 남지 않아야 한다.
- **FR-007**: 세부옵션이 없는 보기에서는 옵션 영역이 비거나 숨고 레전드는 계속 보여야 한다.
- **FR-008**: Node labels·Relationship types **레전드는 화면에 한 곳(노드패널)에만** 표시되어야 한다. 진행 패널은 진행률·상태만 표시한다.
- **FR-009**: Navigator 트리의 **모두 펼치기/모두 접기**는 비개발자도 즉시 의미를 알 수 있는 명확한 아이콘이어야 한다(현재 ⊞/⊟ 모호).
- **FR-010**: Navigator 패널을 **접고 펴는 토글**이 직관적이어야 하며, 접힘/펴짐 상태가 명확히 보여야 한다.
- **FR-011**: 트리 들여쓰기 간격과 상태 표시 점 크기는 계층이 빽빽하지 않게 구분되는 표준 밀도여야 한다.
- **FR-012**: 노드 라벨 색상은 **서로 구분되게(유사색 충돌 최소) 배정되는 것을 기본값**으로 하며, 같은 라벨엔 같은 색이 재현 가능하게 유지되어야 한다.
- **FR-013**: 본 변경은 **기존 보기 동작 자체(모듈간/영역/건강/읽기/쓰기의 결과)·노드 드래그·캔버스 동작을 바꾸지 않는다**(배치/접근 위치만 재구성, 회귀 0).
- **FR-014**: 모든 컨트롤·옵션·아이콘은 **비개발자 기준으로 쓰기 편해야** 한다(라벨/툴팁이 평이하고, 클릭 동선이 짧고, 어디서 무엇을 하는지 일관).
- **FR-015**: 노드 선택 시 노드패널 상단 식별 영역의 **라벨 배지는 그 라벨의 색으로 표시**되어, 사용자가 "지금 보는 게 무슨 종류 노드인지"를 색으로 즉시 안다. 그 색은 **그래프 캔버스에서 같은 노드가 쓰는 색과 동일**해야 한다(같은 라벨=같은 색, 단일 색 소스 재현). 색약 고려해 라벨 텍스트는 항상 함께 표기한다(색은 보조).
- **FR-016**: 노드 선택 시 노드패널은 **항상 노드 종류별 친화적 카드**(식별→개요→본문→연결)로 표시하며, 원시 키-값 나열(raw dump)을 노드에 쓰지 않는다(원시 표는 관계 선택 시에만). 카드 미해당 종류는 폴백 카드가 동일 골격으로 처리한다.
- **NFR(구현)**: 정렬·간격은 매직 px 패딩/마진이 아니라 레이아웃 프리미티브(flex/grid·intrinsic·상대단위·CSS변수)로 — 다해상도·임베드에서 견고. 색은 `getNodeColor` 단일 함수 재사용(DRY). 미사용 분기/속성은 제거(클린코드).

### Key Entities *(데이터 관련 — 표시/상태)*

- **보기 모드(View Mode)**: 그래프를 보는 한 가지 렌즈(모듈간 상호작용·영역·건강 등). 이름, 활성 여부, 선택적 세부옵션 집합을 가진다. 앞으로 개수가 늘어난다.
- **보기 세부옵션(View Option)**: 특정 보기에서만 의미 있는 토글/선택(읽기만·쓰기만·DB링크만 등). 해당 보기에 소속.
- **레전드(Legend)**: 현재 그래프의 Node labels·Relationship types 목록과 색. 화면에 한 곳만 존재.
- **이름 표시(Naming)**: 물리명/논리명 — 보기와 독립인 전역 표시 토글.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 그래프 화면 첫 화면에서 캔버스 위 컨트롤 수가 **2개 이하**(이름 토글 + 보기 선택)다.
- **SC-002**: 보기 모드가 N개에서 N+1개로 늘어도 **상단 컨트롤 수·레이아웃은 불변**이다(보기 선택 목록만 1개 증가).
- **SC-003**: 보기별 세부옵션은 **항상 같은 위치(노드패널)** 에서 발견되며, 보기 전환 시 이전 옵션 잔여 표시가 **0건**이다.
- **SC-004**: Node labels·Relationship types 레전드가 화면에 **정확히 1곳**만 나타난다(중복 0).
- **SC-005**: 비개발자 사용자가 안내 없이 ① 보기 바꾸기 ② 그 보기 세부옵션 켜기 ③ 트리 모두 펼치기/접기 를 **첫 시도에 성공**한다.
- **SC-006**: 라벨 20종 이상에서 인접 라벨 간 색이 육안 구분되며, 기존 보기 결과(모듈간/영역/건강/읽기/쓰기)·드래그·캔버스 동작에 **회귀 0건**.
- **SC-007**: 노드를 고르면 노드패널 식별 배지 색이 **그래프상 같은 노드 색과 일치**하고(서로 다른 라벨은 다른 색), 노드 상세는 항상 친화적 카드로 뜬다(노드에 원시 키-값 표 노출 0건).

## Assumptions

- 대상 사용자는 **비개발자에 가깝고**, 쓰기 편함(직관성·짧은 동선·일관 위치)이 최우선 기준이다.
- 기존 보기 4종(모듈간 상호작용·영역·건강) + 관계필터(읽기/쓰기)의 **로직·결과는 그대로** 두고, 위치·접근 방식만 재구성한다.
- 노드패널(NodeDetailPanel)은 "노드/관계 선택 시 상세" + "비선택 시 보기옵션+레전드" 두 역할을 한 컴포넌트 자리에서 담당한다.
- 색상 구분은 라벨 텍스트로 의미를 보장하는 보조 수단이며, 색 자체가 유일 식별자는 아니다(색약 고려, 라벨 항상 표기).
- 데스크톱(Electron) 임베드·standalone 양쪽에서 동일 동작하며, 그래프 데이터·게이트웨이 계약은 불변(헌법 I·III 준수).
- 좌측 Navigator 트리 개선(아이콘·토글·간격·점)은 016/017 후속이며 본 스펙에 함께 포함한다.
