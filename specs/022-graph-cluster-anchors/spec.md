# Feature Specification: 그래프 보기 — 클러스터 분리 + 그룹 앵커(대표노드) + 성능

**Feature Branch**: `main` | **Created**: 2026-06-20 | **Status**: ✅ 구현완료·라이브검증(2026-06-20) — 상세 tasks.md

**Input**: 라이브 리뷰에서 누적 확인된 근본 문제 — 영역(헐)이 겹치고, 노드를 하나씩 옮겨야 하고, 상호작용 때 force 레이아웃이 수동 배치를 뭉개고, 헐-드래그가 복잡. 사용자 합의: **그룹별로 화면을 분리 배치 + 그룹 대표(앵커) 노드를 끌어 그룹 통째 이동**(노드 하나하나 X). 전부 UI 가독성용 → **프론트 전용·재분석0·백엔드0**.

## 배경 — 왜 재설계 (021 헐/드래그 부분 supersede)
021의 Minkowski 헐 렌더·dpr 수정·콘솔·필터정리는 **유지**(커밋 13a8310). 단 **레이아웃·드래그 모델**을 교체한다:
- (구) force 레이아웃 → 노드 뒤섞임 → 헐 겹침 + 헐-드래그(복잡·줌버그).
- (신) **그룹별 클러스터 분리 배치 + 위치 고정(free) + 그룹 앵커 드래그.**

## 데이터 사실 (Neo4j 전수확인 — 추측0)
- 앵커 실노드: `PACKAGE(RWIS)`×1, `SCHEMA(RWIS)`×1, `FILE`×9. (이름 같아도 PACKAGE≠SCHEMA, 다른 노드)
- 그룹 엣지: `FILE-BELONGS_TO→PACKAGE`, `TABLE-BELONGS_TO→SCHEMA`, `MODULE:EXTERNAL-BELONGS_TO→PACKAGE`, `FILE-HAS_MEMBER→루틴`.
- 속성: 루틴 `file_path`·`component_id`(희소: 1 컴포넌트 3 PROC)·`risk_level`(low7/med2).
- ⇒ **모든 그룹키·앵커가 기존 데이터에 존재.** 백엔드 추가 0.
- framework 전략(CLASS⊃METHOD)은 동형 가정·런타임 미검증(RWIS=dbms만).

## User Scenarios *(mandatory)*

### US1 - 클러스터가 화면에서 분리된다 (P1) 🎯
보기를 켜면 그룹(모듈/테이블/external/군집)이 **화면의 서로 다른 구역에 자동 배치**되어 **영역이 겹치지 않는다**. 노드를 수동으로 안 떼어놔도 된다.
**Acceptance**: 모듈간 → 모듈 클러스터·테이블 클러스터·external 클러스터가 **떨어져** 보이고 각 헐이 안 겹친다.

### US2 - 그룹 앵커로 그룹 통째 이동 (P1)
각 그룹 중앙에 **대표(앵커) 노드**가 있고, 그걸 끌면 **그 그룹의 멤버 전부 + 헐이 함께** 이동한다(다른 그룹 불변). 노드 하나하나 안 옮겨도 된다.
**Acceptance**: 앵커 드래그 → 그룹 멤버·헐 통째 이동, 타 그룹 좌표 불변. 멤버 개별 드래그도 가능.

### US3 - 수동 배치가 고정된다 (P1)
배치 후 **노드 선택/추가/상호작용해도 재정렬(force 재실행)로 뭉개지지 않는다**.
**Acceptance**: 노드 클릭·앵커 이동 후, 다른 노드 선택해도 위치 그대로.

### US4 - 헐이 노드를 정확히·줌무관 감싼다 (P2)
헐은 어떤 줌·해상도(dpr)에서도 노드 밖으로 안 삐진다. (021 Minkowski+dpr 유지 + NVL 정확 노드기하 or 줌상한)
**Acceptance**: 극단 줌에도 노드가 헐 안.

### US5 - 라벨 가독성 (P2)
앵커/그룹 라벨이 노드와 안 겹치고 줌 무관하게 또렷.

### Edge Cases
- 패키지/스키마 1개(RWIS) → 모듈·테이블·external 3 클러스터로 분리(패키지 내부는 1덩어리).
- component_id 희소(미보유 루틴 다수) → 미보유는 별도 "기타" 처리 or 군집서 제외(혼란 방지).
- 합성 앵커 id 충돌 0(접두사 `__anchor__:`).

## Requirements *(mandatory)*
- **FR-001**: 보기 진입 시 그룹키로 멤버를 클러스터링, 각 클러스터를 **분리된 구역에 배치**(겹침 최소).
- **FR-002**: 그룹별 **앵커 노드** — 실노드(PACKAGE/SCHEMA/FILE) 있으면 사용, 없으면(component_id) **프론트 합성**. 앵커↔멤버 매핑은 프론트 메모리.
- **FR-003**: **앵커 드래그 = 그룹 멤버+앵커 동일 델타 이동**(`setNodePositions`), 헐 추종, 타 그룹 불변.
- **FR-004**: 초기 배치 후 **위치 고정**(free layout/no re-layout) — 상호작용에 재정렬 0.
- **FR-005**: 헐은 줌·dpr 무관 노드 enclosure(021 유지). 줌 상한 or NVL 정확기하로 삐짐 0.
- **FR-006**: 그룹키·앵커는 **기존 데이터 파생**(백엔드 0). 보기별 매핑은 아래 표.
- **FR-007**: ★성능 — rAF는 상호작용 중에만(idle 정지), 계산 캐싱(convexHull·계층맵), hit-test=NVL `getCanvasNodesAt`, 리스너·타이머·rAF·NVL 인스턴스 **누수 0**(cleanup 전수).
- **FR-008**: 회귀 0 — 드롭·1-hop·필터·논리명·스트림·색상크래시0 유지.

### 보기별 앵커 매핑
| 보기 | 그룹키 | 앵커 | 멤버 |
|---|---|---|---|
| 영역(구조) | package→file | PACKAGE(실)→FILE(실) | 루틴 |
| 협력 군집 | component_id | 합성(군집명) | 그 컴포넌트 루틴 |
| 모듈간 | package / schema / external | PACKAGE / SCHEMA / external合成 | 모듈 / 테이블 |
| 건강 | package(색=risk) | PACKAGE(실) | 위험색 루틴 |

## Success Criteria *(mandatory)*
- **SC-001**: 영역 겹침 0(클러스터 분리). **SC-002**: 앵커 드래그로 그룹만 이동(타 그룹 불변).
- **SC-003**: 상호작용 후 재정렬 0(위치 고정). **SC-004**: 줌·dpr 무관 헐 삐짐 0.
- **SC-005**: 성능 — idle CPU rAF 0, 누수 0(감사 통과). **SC-006**: 백엔드0·재분석0·회귀0.

## Assumptions / 범위 밖
- 백엔드 노드/속성/모델 무변경. 그룹·앵커는 프론트 합성.
- 021의 헐 렌더·dpr·콘솔·필터는 유지(중복 X). 본 스펙은 021의 **레이아웃·드래그**를 supersede.
- framework 계층은 구현 시 확인.
