# Feature Specification: Analysis Scope Browser (분석 범위 브라우저)

**Feature Branch**: `014-analysis-scope-browser`

**Created**: 2026-06-15

**Status**: Draft

**Input**: User description: "analyzer 경로모드 입력 UI를 '로컬 파일시스템 브라우저'로 개선 — 좌측 FS 트리 + 파일 미리보기 + 포함/제외 선택, 선택된 범위만 분석. DDL/SP 분류는 기존 자동 유지."

## Overview (배경)

Electron(로컬 경로) 모드에서 analyzer는 로컬 폴더를 직접 읽는다(업로드 없음). 그런데 지금 입력 화면은 **폴더 경로 텍스트 + "분석 시작" 버튼**뿐이라, 사용자는 폴더 안에 무엇이 있는지 못 보고(가시성 없음), 무엇이 분석될지 알 수 없으며, 범위를 좁힐 수 없다. 폴더 전체가 통째로 스캔되니 테스트 코드·벤더 라이브러리·무관 디렉터리까지 다 분석에 들어가 — 느리고 지저분하고 LLM 비용이 커진다.

이 기능은 그 빈약한 입력을 **로컬 파일시스템 브라우저**로 바꾼다. 사용자는 실제 폴더 트리를 보고, 파일 내용을 미리보고, 파일/폴더를 포함·제외해서 **선택된 범위만** 분석되게 한다. 엔진의 자동 분류(어떤 파일이 표 정의인지 프로시저인지, 무슨 언어인지)는 **불변** — 그건 기계의 몫으로 둔다. 두 축을 의도적으로 분리한다.

- **분류(무엇인가)** = 엔진, 자동, 내용 기반. 사용자가 DDL/프로시저를 손으로 라벨링하지 않는다.
- **범위·가시성(무엇을 보고/분석할지)** = 사용자, UI로 통제.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 분석 전에 소스를 보고 범위를 정한다 (Priority: P1)

로컬 코드/DB 폴더를 가리키는 분석가가, 폴더 트리를 보고 어떤 파일/폴더를 포함할지 골라서 관련 코드만 분석되게 한다(테스트·벤더·빌드·무관 디렉터리 제외).

**Why this priority**: 핵심 가치. 이게 없으면 사용자는 깜깜하고(가시성 없음) 무력하다(범위 통제 없음); 폴더 통째 스캔이 근본 고통(느림·잡음·비용). 트리 + 포함/제외가 범위 분석을 구동하는 것이 가치를 전하는 최소다.

**Independent Test**: 경로 모드에서 로컬 폴더를 열고 트리를 펼쳐 하위 폴더(예: `test/`)를 제외한 뒤 분석 시작 — 분석 결과에 제외 폴더의 것이 하나도 없는지 확인.

**Acceptance Scenarios**:

1. **Given** 선택된 로컬 폴더, **When** 입력 화면이 열린다, **Then** 폴더의 실제 계층 트리(폴더 펼침/접힘, 파일 목록)가 표시된다.
2. **Given** 트리가 보인다, **When** 사용자가 폴더를 제외, **Then** 그 폴더와 모든 하위가 제외 표시되고 시각적으로 약화된다.
3. **Given** 일부가 제외됨, **When** 분석 시작, **Then** 포함된(제외 안 된) 파일만 분석 엔진으로 보내진다.
4. **Given** 섞인 `.sql`(표 정의 + 프로시저)이 포함됨, **When** 분석 실행, **Then** 엔진이 기존대로 DDL·프로시저를 자동 분류한다(수동 분리 불필요).

---

### User Story 2 - 결정 전에 파일을 미리본다 (Priority: P2)

분석가가 트리에서 파일을 클릭해 화면에서 내용을 읽고, 그 파일이 분석 범위에 속하는지 판단한다.

**Why this priority**: 정보에 근거한 포함/제외는 파일 내용 가시성이 필요하다. 없으면 이름으로만 제외한다. 가치 있으나 트리+제외(US1)가 이미 핵심 범위 통제를 제공한다.

**Independent Test**: 트리에서 파일을 클릭해, 분석을 시작하지 않고도 그 텍스트 내용이 읽기 전용 미리보기 영역에 표시되는지 확인.

**Acceptance Scenarios**:

1. **Given** 트리가 보인다, **When** 텍스트 파일을 선택, **Then** 내용이 읽기 전용 미리보기에 표시된다.
2. **Given** 비텍스트/바이너리 또는 아주 큰 파일을 선택, **When** 미리보기 시도, **Then** 렌더하지 않고 명확한 안내를 표시한다.

---

### User Story 3 - 똑똑한 기본값과 선택 기억 (Priority: P3)

반복 사용자를 위해, 흔한 잡음(의존성·빌드·버전관리·테스트 디렉터리)은 기본 제외되고, 제외 선택은 폴더별로 기억돼 매번 같은 설정을 다시 안 해도 된다.

**Why this priority**: US1 위의 편의 계층 — 반복 작업을 줄이고 깨끗한 범위로 유도하지만, 없어도 기능은 동작한다.

**Independent Test**: 의존성 디렉터리(예: `node_modules`)가 든 폴더를 열어 기본 제외되는지 확인; 다른 폴더를 제외하고 같은 프로젝트를 나중에 다시 열어 이전 제외가 복원되는지 확인.

**Acceptance Scenarios**:

1. **Given** 잘 알려진 잡음 디렉터리가 든 폴더, **When** 열림, **Then** 그 디렉터리들이 기본 제외된다(다시 포함 가능).
2. **Given** 사용자가 프로젝트의 제외를 바꿈, **When** 같은 프로젝트를 다시 열기, **Then** 이전 포함/제외 상태가 복원된다.

---

### Edge Cases

- **빈 폴더 / 분석 가능한 파일 없음**: 아무것도 분석되지 않음을 설명하는 빈 상태 표시.
- **전부 제외됨**: 포함 범위가 비면 "분석 시작" 비활성(또는 경고).
- **매우 큰 폴더(수천 파일)**: 트리가 점진 로드/응답성 유지; 범위 수 계산 가능.
- **접근 불가/권한 거부 경로**: 비차단 안내로 표시; 나머지 트리는 사용 가능.
- **바이너리/초대형 파일**: 미리보기에 렌더 안 함; 명확한 안내.
- **로드 후 디스크에서 폴더 내용 변경**: 사용자가 트리 새로고침으로 재동기화.
- **심볼릭 링크/순환 링크**: 무한 확장 유발 안 함.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 경로 모드에서 선택된 로컬 폴더를 탐색 가능한 계층 트리(폴더 펼침/접힘, 파일 목록)로 표시해야 한다.
- **FR-002**: 사용자는 임의의 파일/폴더를 포함·제외할 수 있어야 하며, 폴더 제외는 그 하위 전부를 제외한다.
- **FR-003**: 분석 시작 시 포함된(제외 안 된) 범위만 분석 엔진으로 보내야 한다.
- **FR-004**: 사용자는 선택한 파일 내용을 분석 시작 없이 읽기 전용으로 미리볼 수 있어야 한다.
- **FR-005**: 어떤 항목이 분석 대상인지/무시되는 타입인지(예: 미지원 확장자) 표시해, 무엇이 중요한지 알 수 있게 해야 한다.
- **FR-006**: 잘 알려진 잡음 디렉터리(의존성·빌드 산출물·버전관리·테스트)는 기본 제외하되(SHOULD), 사용자가 다시 포함할 수 있어야 한다.
- **FR-007**: 프로젝트의 포함/제외 선택을 세션 간 기억해야 한다(SHOULD).
- **FR-008**: 포함 범위에 대한 기존 자동 언어·DDL/프로시저 분류를 보존해야 한다 — 수동 DDL/프로시저 라벨링을 도입하지 않는다.
- **FR-009**: 시작 전에 결과 범위 크기(예: 분석될 파일 수)를 보여, 선택의 효과를 미리 볼 수 있게 해야 한다.
- **FR-010**: 빈/접근불가/전부제외 범위를 우아하게 처리해야 한다(명확한 상태; 빈 범위로 분석 시작 안 함).
- **FR-011**: 이 기능은 로컬 경로(Electron 임베드) 모드 전용이다; 브라우저 업로드 흐름은 영향받지 않아야 한다.

### Key Entities *(include if feature involves data)*

- **Source Tree Node(소스 트리 노드)**: 선택된 프로젝트 루트 아래의 파일/폴더 — 경로·이름·타입(파일/폴더)·자식·크기·분석 대상 여부.
- **Scope Selection(범위 선택)**: 트리에 대한 프로젝트별 포함/제외 결정 집합. 실제 분석될 파일 목록으로 해석됨.
- **File Preview(파일 미리보기)**: 선택한 파일의 읽기 전용 내용. 바이너리/초대형은 렌더 불가 상태.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 분석 시작 전에, 사용자는 분석될 파일 전체 집합을 볼 수 있다(숨은 통째 스캔 없음).
- **SC-002**: 사용자가 폴더를 제외하면, 그 폴더의 파일이 분석 결과에 하나도 나타나지 않는다.
- **SC-003**: 의존성/테스트/빌드 디렉터리 제외가 분석 파일 수(따라서 실행 시간·LLM 비용)를 측정 가능하게 줄인다.
- **SC-004**: 사용자가 같은 화면에서 임의 텍스트 파일 내용을 미리볼 수 있다.
- **SC-005**: 이전에 설정한 프로젝트를 다시 열면 포함/제외 선택이 복원된다.
- **SC-006**: 일반적 저장소의 분석 범위 검토·설정을 1분 이내에 마칠 수 있다.
- **SC-007**: 포함 범위에 대한 분석 산출물 품질이 기존 폴더 통째 동작과 동일하다(같은 파일에 같은 DDL/프로시저 분류).

## Assumptions

- **경로 모드 전용**: Electron 임베드 로컬 경로 흐름(호스트가 프로젝트 루트 주입) 대상. 브라우저 업로드 모드는 현행 입력 UI 유지.
- **로컬 파일시스템 접근은 호스트 경유**: 렌더러는 로컬 디스크를 직접 못 읽는다; 트리 목록과 파일 내용은 데스크톱 호스트의 파일시스템 접근(IPC)으로 온다. 호스트의 기존 파일탐색기/FS 기능 재사용을 우선 검토(plan에서 확정).
- **제외는 opt-out**: 기본은 루트 아래 전체 포함(FR-006의 알려진 잡음 기본 제외 제외); 사용자가 제외로 좁힌다. "테스트/벤더 제외" 흐름과 일치.
- **범위는 통합 입구(파서)로, analyzer 경로 모드가 아님**: 포함 범위는 파서의 단일 입구(antlr 스펙 006 "입구 통일")로 전달돼, 선택 파일을 표준 `data/` 폴더로 반입한다. analyzer는 이후 `data/`만 소비(analyzer 스펙 014 "data/ 단일 소비")하며, 레거시 `project_root` 경로 모드는 제거되므로 이 UI는 그것에 의존해서는 안 된다. 범위 계약(포함 vs 제외 목록, 경로 의미)은 antlr 스펙 006과 공유하는 plan 결정.
- **분류 파이프라인은 (이 UI가) 건드리지 않음**: DDL vs 프로시저·언어 분류는 파서의 몫이며 **내용**으로 한다(antlr 스펙 006); 이 UI는 *어떤 파일*이 범위인지와 사용자에게 어떻게 보일지만 정한다. 파일을 DDL/source로 라벨링하지 않는다.
- **호스트 UX와 일관**: 트리/미리보기 경험은 가능한 한 robo-architect Code 탭 파일탐색기와 일관되게.

## Dependencies & Cross-Service Impact

- **데스크톱 호스트(robo-architect)**: 트리+미리보기용 로컬 파일시스템 접근(디렉터리 목록·파일 읽기), 호스트 IPC 경유.
- **↓ antlr-code-parser (스펙 006 "입구 통일")**: 선택 범위를 받아 `data/`로 반입한다; 이 UI의 범위 출력이 그 입구의 입력이다. **공유 계약** — plan에서 함께 정의.
- **↓ robo-data-analyzer (스펙 014 "data/ 단일 소비")**: `data/`만 소비; 이 UI는 analyzer 경로 모드(제거 중)를 구동하는 경로를 보내서는 안 된다.
- **코디네이션 세트**: 이 스펙은 세 스펙(frontend 014 ↔ antlr 006 ↔ analyzer 014) 중 하나로, 함께 "범위 → 통합 입구 → data/ → analyzer"로 옛 업로드-vs-경로 분기를 대체한다.
